# JOEDESIGN Optical / Detail Polish Gate v1

**Decision:** `OPTICAL_CORE = DEFERRED; no demonstrated need before competition`

## Basis

The v0.1 roadmap requires an Optical / Detail Polish Core only when preceding actual-render evidence demonstrates a recurring defect that is not already handled by existing Craft rules.

Current evidence does not demonstrate that need.

- Spatial / Hierarchy already covers alignment, rhythm, semantic spacing, and optical micro-correction boundaries.
- Typography / Scale already covers fine typographic hierarchy and actual-render inspection.
- Color / Contrast covers border/surface restraint where color and separation are involved.
- Imagery / Focal covers image framing, focal balance, crop, and visual dominance.
- Composition / Anti-template Smoke I preserved one candidate alignment failure and resolved it through the existing Composition contract without adding a new runtime doctrine.

## Deferred candidates

The following remain available as v0.2 or post-competition additions if repeated evidence demonstrates a gap:

- optical alignment
- icon/text balance
- border/elevation restraint
- radius consistency
- micro-spacing exception discipline
- fine typography optical correction

## Constraint

Do not add an Optical public skill, rule database, scorer, or mandatory review layer before competition.

If competition or real project evidence later shows a recurring failure not covered by current Craft Core, reopen this gate with that exact evidence.
