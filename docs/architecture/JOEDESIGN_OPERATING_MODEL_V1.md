## Role and authority

| Responsibility | Owner |
| --- | --- |
| Functions, information, states, behavior and recovery | Product authority |
| Relationship interpretation, project composition, original/result gap diagnosis | JOEDESIGN |
| Code, responsive/state implementation and self-observation of actual output | Implementer |
| Environment, isolation, execution records, verification management, handoff | Controller / existing lifecycle owner |
| Material visual approval and acceptance of an exact result | User |

These responsibilities do not require separate agents or JOEFLOW. The controller
does not add a new design interpretation or remove the implementer's observation.

Product meaning constrains all work. Scoped approved original visual material and
APPROVED root DESIGN.md are visual authority; expose conflicts between them.
Ordinary references are advisory. Craft/defaults assist unresolved decisions and
never override an approved target. Current code and tool output do not self-approve.

## Minimal flow

Approved target: original/version/surface/state + real assets → only needed
project/native-role decisions → implementation → actual comparison with original.

Ordinary reference: observed relationship → scoped unapproved proposal → authorized
bounded proof → explicit user approval before material promotion. No fixed candidate
count, mandatory full craft form or guarantee of autonomous original design quality.

Source material reaches the implementer directly; interpretation supplements it.
Distinguish measured/estimated/proposed/approved values. Still imagery cannot prove
motion or unseen responsive behavior; its viewport cannot authorize content deletion.

## Durable state / implementation

Keep one root DESIGN.md with compact source pointers, approval scope, necessary
project decisions and unknowns. Preserve APPROVED Rev N during DRAFT Rev N+1 and
retain custom sections. No additional authority sidecar. The Implementation Bridge
is derivative, using healthy project-native roles; structured tokens are optional
data, not a parser/lint/export pipeline or vendor dependency.

For an authorized local change, inspect the current target, correct the affected
relationship, observe again and preserve protected regions. Unresolved Product
meaning returns only its affected scope to Product/user while independent work
continues. Repeated failure triggers diagnosis, not automatic full-page regeneration.

## Evidence and boundaries

Technical/token success ≠ Product conformance ≠ visual conformance ≠ user acceptance.
For material claims: expected relationship → observed fact → PASS/FAIL/UNVERIFIED.
Required failure or missing observation cannot be buried by unrelated passing checks.
The implementer reports the useful boundary; controller maintains operational records.

TrackE CLOSED; specialist value NOT TESTED. Functional text checks are not design
quality comparisons. Real-project visual validation with new approved material/assets
is PENDING. No new platform, database, router/scorer, public skill, image generation
dependency, competitor-method integration or BIO production belongs to this scope.
