## Scope and decisions

One `$joedesign` translates approved visual material and selected reference
relationships into project-specific implementation decisions while preserving
Product meaning. Approved-target implementation is primary; unresolved reference
exploration is conditional. No reliable autonomous-original-design quality promise.

1. Identify approval scope/version/surface/state. A user-supplied image alone is
   not approved. Sufficient approved inputs go directly to the needed delta,
   without compulsory alternatives or repeated documentation.
2. Select only relationships needed for this task: source observation →
   preserve/change → concrete project decision → observable difference. Distinguish
   measured, estimated, proposed and approved values. No inferred hover/motion
   facts from stills; viewport bounds never authorize clipping required content.
3. Original material and real assets reach the implementer directly. Compact
   translation supplements them, never replaces them. Expose authority conflicts.
   One root DESIGN.md retains source pointers, decisions, approval scope and unknowns.
4. Product owns meaning; JOEDESIGN visual relationships and gap diagnosis;
   implementer code/responsiveness/states and self-observation; controller execution,
   records and handoff, not new visual interpretation. No mandatory extra agent.
5. Keep relationship-based craft and native role reuse. Defaults apply only to
   unresolved areas and never override approved sources. Reduce duplicate gates,
   fixed candidate count, all-craft reporting and experiment administration.

Keep the three-file install package self-contained. No new conditional references
are needed: concise craft principles stay in SKILL.md; the template is loaded only
when creating or materially updating durable decisions. No mandatory sidecar.

response and execution stream are separate files/hashes; model/effort/thread,
