## 변경 범위

기존 계약 검사기에 `run`을 추가했다. 명시된 프로젝트와 계약을 입력으로
Codex 실제 프로세스, 기존 Playwright/Edge 런타임, R/C1/조건부 C2,
새 컨텍스트의 Critic, 제한된 수정 및 재개를 연결한다.
모델 설정은 호스트 설정을 사용하며 설치·배포·push는 수행하지 않았다.
기존 `skills/joedesign/`과 역사적 평가 자료는 변경하지 않았다.

실행기는 원본 일곱 계약 파일을 덮어쓰지 않는다. 계약·스킬·실행 코드·프로젝트·
수집 증거의 식별자를 기록하고, 읽기 전용 검토 중 프로젝트 변경, 증거 변경,
중복 실행, 부분 수정 후 무분별한 재실행을 차단한다. 구조 FAIL은 즉시
재설계로 돌리고 같은 항목이 두 회차 연속 미해결이면 국소 수정을 중단한다.

작업은 수행하지 않았다. 회귀는 변경 후 필요한 범위의 보존 확인이다.

## 실제 실행 중 발견하고 수정한 오류

첫 실험은 접근성 검토에서 `UNKNOWN_REVIEW_EVIDENCE`로 중단됐다.
검토자가 잠긴 원본 ID `original`과 현재 캡처를 함께 인용했는데 실행기가
캡처 ID만 허용하던 오류였다. 원본 인용을 허용하되 PASS에는 같은 대상·종류의
실제 캡처가 필요하도록 수정했다. 존재하지 않는 ID나 원본만으로 내린 PASS는
계속 차단하며, 잘못된 검토는 완료 캐시에 넣지 않는다.

같은 실험에서 검토자는 키보드 포커스 관찰 누락을 정확히 지적했다.
선택자를 지정한 Tab 입력이 버튼에서 포커스를 이동시키던 수집 설정이었다.
페이지 키보드 입력과 활성 요소·`:focus-visible` 기록을 추가하고 Tab → Enter,
포커스 유지 assertion으로 다시 관찰했다. 실패 자료와 수정 전 판정은 보존했다.

수정 후 실제 실행에서는 UX 담당 R 검토가 240초 제한을 넘겼다. 실행기는
자신이 시작한 프로세스 트리만 종료하고 BLOCKED를 기록했다. 재개 시에는
원래 소스 스냅샷과 동일 입력·스킬 경로·로컬 주소를 사용했다. 최초 BLOCKED
보고서, 재개 전 상태와 실패한 attempt 디렉터리를 별도로 보존했다.
시간 제한을 성공으로 바꾸거나 구현부터 다시 실행하지 않았다.
재개도 같은 제한에서 시간 초과로 끝났고, 두 실패를 모두 보존했다.

실험 프로젝트는 버튼 문구 하나를 `Select Beta`에서 `Compare Beta`로 바꾸는
합성 페이지다. 사용자 실프로젝트나 승인된 디자인 품질 벤치마크가 아니다.
390×844의 선택 상태와 기존 구조 보존만 관찰한다. 넓은 화면·전체 접근성·
스크린리더 실제 출력·새로운 시각 방향의 우수성을 평가하지 않았다.

## 자료와 재현 범위

원자료 위치: `.local/execution-integration-20261006/`.
`live/`는 실패한 첫 실행, `live-r2/`는 수정 후 실행이다. 각 역할의 입력,
실제 SKILL.md 경로·해시, 새 context ID, native JSONL, 결과와 실제 PNG가 남아 있다.
원자료는 로컬 전용이며 Git 복제본만으로 제공되지 않는다. manifest에는
관찰 범위, 소스 식별자, 원자료 해시와 요약을 저장한다. 해시는 로컬 무결성
비교용이며 인증된 호스트 receipt가 아니다.
[기계 판독 manifest](manifest.json)에 최종 소스와 실제 실행 스냅샷을 따로 기록했다.

두 번째 실제 실행은 시작 전에 저장한 `runtime-source-hashes.json`의 소스로
수행됐다. 그 바이트와 일치하는 `package-snapshot/`을 보존했다. 이후 추가한
구조 실패·연속 미해결 중단 규칙과 재개 시 RUNNING 상태 복구는 최종 코드의
별도 회귀 검사로 검증했다.
그 추가 분기의 실제 모델 재설계 효과는 이번 합성 실행의 입증 범위가 아니다.
