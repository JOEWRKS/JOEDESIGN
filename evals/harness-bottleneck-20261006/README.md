# 검토 실행 병목 보강 — 2026-10-06

이 기록은 [첫 실행 연동 검증](../harness-execution-20261006/README.md)의
BLOCKED 이후 후속 작업이다. 이전 실패·입력·결과는 변경하지 않았다.

## 진단과 수정

두 UX 실패 모두 파일 읽기는 정상 종료했고, 그 결과 이후 최종 답변이 오지
않아 240초 제한에 걸렸다. 파일 I/O 자체가 240초 걸린 것은 아니다.
실제 native 입력에는 `--image`의 가변 인자로 삼켜진 `-`가 추가 이미지로
기록돼 있었다. 서로 다른 경로의 동일 이미지도 중복 첨부됐다.

1. stdin 프롬프트 앞에 `--`를 넣어 이미지 인자와 구분했다. 실제 native
   입력에서 잘못된 `-` 이미지가 사라진 것을 확인했다.
2. 동일 SHA-256의 이미지만 한 번 첨부한다. 6개 경로가 고유 이미지 4개로
   전달되며 원본 경로·해시·별칭과 상태별 프레임 목록은 보존한다.
3. 전문 검토의 범위를 배정된 항목과 관련 참고자료로 명확히 했다. 스킬 원문,
   도구 접근, 미관찰 항목의 UNVERIFIED 규칙은 유지한다.
4. 실제 수집 JSON과 계약에 명시된 관련 프로젝트 소스를 해시·원문과 함께
   입력에 전달한다. 같은 파일을 다시 읽는 왕복을 줄이고, 새로운 조사가
   필요하면 도구를 사용할 수 있게 했다.
5. `--review-only`를 추가해 기존 구현을 다시 작성하지 않고 새 관찰·전문 검토·
   Critic을 수행한다. 이 모드는 수정 실패를 이유로 쓰기 권한을 얻지 않는다.

## 단계별 실제 관찰

| 실행 | 변경·조건 | 결과 |

| 이전 UX 두 시도 | 원래 입력, 각 240초 | 모두 시간 초과 |
| UX 단독 비교 | 인자 구분·이미지 중복 제거·범위 명확화, 같은 모델·240초 | 약 20초, 구조화된 판정 반환 |
| 중간 전체 검토 | 위 세 가지 수정만 적용 | Technical에서 자료를 읽은 뒤 시간 초과; 실패 보존 |
| Technical 단독 비교 | 수집 기록·관련 소스 직접 전달, 같은 모델·240초 | 약 13초, 구조화된 판정 반환 |

시간 제한을 늘리거나 모델을 바꿔 얻은 결과가 아니다. 실제 설정은
`gpt-6-astra`, reasoning `high`였다. 비교 결과는 입력 전달 방식을 보완한
효과를 보여주지만, Codex 내부의 응답 지연 원인을 단일 요인으로 확정하거나
앞으로 모든 도구 호출의 지연이 사라진다고 입증하지는 않는다.

## 최종 실제 검수 결과

**REVIEW_COMPLETE_UNCERTIFIED**로 완료됐다. 현재 후보의 실제 브라우저 관찰,
R 5개 역할 실행, C1 4개 역할 실행, 새 컨텍스트 Critic까지 총 10개 역할이
구조화된 판정을 반환했다. 미해결 판정은 없고 `approved`는 false다.
R/C1 충돌이 없어 C2는 호출되지 않았다. C2·수정 분기의 검증은 기존 자동
fixture 결과와 구분하며, 이번에 실제 모델로 실행됐다고 주장하지 않는다.

- 최종 UX R: **17.1초**. UX C1: **34.8초**.
- 최종 완료된 역할 실행 시간: **11.8–34.8초**. Critic: **28.2초**.
- 마지막 V/C1에서는 별도로 한 번의 240초 시간 초과가 있었다. 같은 코드·
  입력·모델·시간 제한으로 실패한 단계부터 재개하자 **13.8초**에 완료됐다.
  따라서 간헐적인 응답 지연까지 제거됐다고 주장하지 않는다.
- 재개 시 기존 관찰과 완료된 8개 역할의 디렉터리·결과 해시는 그대로였다.
- 프로젝트 내용과 일곱 계약 산출물은 바뀌지 않았다. 완료 후 CLI의
  `--review-only --resume`도 추가 역할 실행 없이 같은 결과를 반환했다.
- Python **104개**, Node **14개**, 총 **118개 검사 통과**, 생략 없음.

입력 전달 문제는 수정했고, 완료 작업을 다시 수행하지 않는 검수·복구 흐름을
실제로 확인했다. 아직 검증하지 않은 전 제품의 처리 속도나 서버 지연을
이 합성 사례의 결과로 일반화하지 않는다.

## 보존과 한계

원자료는 `.local/bottleneck-20261006/`에 있다. `probe-U`,
`probe-technical`, 중간 실패 `full-review`, 최종 검토 `full-review-r2`를
구분한다. 실행 전에 기대사항·코드 해시를 저장했고, 수정 전후 결과를 섞지
않는다. 최종 결과·역할별 시간·원자료 해시는 [manifest](manifest.json)에 남긴다.
로컬 원자료는 Git 복제본에 포함되지 않는다.

이 실험은 기존 합성 페이지의 한 화면·상태를 검수한 것이다. 실프로젝트
디자인 품질, Critic 판단 보정, 연속 모션, 인증된 host receipt, 사용자 수용성은
별도 검증 대상이다. 로컬 검토 완료를 최종 APPROVED로 바꾸지 않는다.
