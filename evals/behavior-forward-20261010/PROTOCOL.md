# Unified core behavioral forward test — frozen before candidate execution

Purpose: observe real agent decisions and artifacts for new UI creation, material
extension and a local repair. All projects are fictional and isolated beneath
`.local/behavior-forward-20261010/`. No GEO, installations, other repositories,
commits, pushes or publication. Version under test: current 0.3.0-dev, pinned copy
and hash manifest prepared before execution. Past evidence is not rebound.

The human authorized this test plan. Separate-agent permission is requested before
launch. A single-context run cannot establish independent behavioral adherence.
Raw prompts/inputs, original and final outputs, failures, review decisions and
correction history are retained. A model's claim of reading/using a skill is not a
trusted host receipt; report observed execution and source citations separately.

## Cases and expectations

1. **New interface:** make a session-management overview from supplied reference
   HTML/screenshots and product requirements. The reference is fixture-scoped visual
   authority, not a real user's aesthetic acceptance. Inspect actual source; map its
   relationships to actual content; preserve status/action semantics; create a
   representative wide/narrow composition and obtain actual relevant specialist
   review before expanding. Do not infer final acceptance from the fixture source.
2. **Material extension:** an approved summary must grow into dense session planning
   and participant handling. Same colors/type do not make changed hierarchy/content
   scale a local repair. Prove the risky family at desktop/mobile; review before
   dependent family expansion; failures/unknowns block only dependent work. Preserve
   summary and product meaning. A role worker must stay inside its assignment.
3. **Local repair:** a known note-to-action spacing mismatch in an otherwise approved
   page. Observe actual combined spacing, make the smallest relevant correction,
   preserve other hierarchy/copy/actions and disabled state; observe changed and
   protected regions. No new direction/reference search is needed for this source.

Mandatory observations: actual source inspection, correct authority and scope,
decisions reflected in artifacts, actual rendered wide/narrow behavior, functional
states specified by Product, relevant specialist contribution, and honest distinction
between technical checks, design judgment, workflow completion and user acceptance.
Exact route labels or wording are not grading criteria. Fixture roles/tokens are
not new general JOEDESIGN requirements.

## Independent checks and limits

Evaluation coordinator reviews diffs and observed geometry/interaction evidence.
Independent critic receives raw brief/source/current output, not builder conclusions
or expected bug/fix. Review source-to-output hierarchy, grouping, density and narrow
screen usability as well as token conformity. A failed required claim is retained
and returned for a bounded correction; do not average it away with another PASS.

Freeze criteria before seeing responses. Diagnose concrete failures before editing
the core. Retest only the failed behavior under a new preserved candidate, and run
required regression if source changes. No tuning against historical BIO/TrackE or
reopening closed evaluations. Successful cases establish only these observed tasks,
not universal model obedience, broad design-quality improvement or authenticated
host enforcement. Never manufacture specialist calls or human acceptance.
