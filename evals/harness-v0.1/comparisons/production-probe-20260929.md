# PEBBLE/01 실제 제작 비교: 기존 A / 개선 B

결론: **개선 Harness의 추가 효과는 이번 단일 과제에서 확인되지 않았다.** 기존 A와 개선 B 모두 사전 고정한 6개 문제를 발견했고, 수정 후 같은 Chrome 화면·조작에서 6개를 해결했다. B가 미적 완성도에서 우월하다는 근거도 없다. 모바일에서는 B의 다이얼 안내가 세 줄로 늘고 RESET 아이콘이 버튼 안에서 다음 줄로 떨어지는 작은 마감 결함이 남았다. A의 안내/버튼은 정돈되어 있다. 데스크톱 제품 카드는 B가 사진을 조금 더 크게 썼지만, 이는 별도의 사용자 평가 없이 우위 판정을 내릴 근거가 되지 않는다.

## 실행과 증거
- 새 제품 사진은 built-in imagegen으로 한 번 만들고 양쪽에 같은 PNG(1536×1024, RGBA, SHA-256 98B0606D6CCA95DDC679A574D31AD0A52616AEA6FAD42A79F113070A618A7D5E)를 복사했다. 원본 프롬프트는 controller/ASSET_PROMPT.md. 평가 모델은 자산 바이트를 수정하지 않았다.
- 같은 JOEDESIGN core, PRODUCT.md, 초기 index.html, 이미지와 초기 Chromium 캡처를 주었다. A는 설치된 기존 Harness 복사본, B는 개선된 소스 Harness 복사본을 읽었다. 모델 gpt-6-astra / high, 각각 독립 실행 1회. `--approve-for-me`로 정상 파일 읽기·수정이 가능했고 양쪽에서 도구 명령 18개가 실행됐다. 오류 이벤트는 없다.
- 기준은 controller/truth.json에 실행 전에 고정했다. 입력 해시는 controller/frozen-inputs.json. 두 모델은 기준표를 보지 않았고, 먼저 FINDINGS.md를 작성한 뒤 index.html을 수정했다. 각 결과의 정적 자체 검증을 최종 판정으로 사용하지 않았다.
- 실제 화면에서는 A/B 모두 사진 비율을 유지하고 제품 전체를 보여준다. 사진 속 구리 다이얼에 조작 영역이 놓였으며, desktop drag는 A 145° / B 129°, mobile drag는 A 139° / B 148°로 반응했다. 같은 장면에서 몸체 사진은 움직이지 않았다. 역방향 제스처는 0°, End는 270°, RESET은 0°로 동작했다. IVORY/CLAY 선택은 pressed 상태와 사양을 바꾸고, 사진은 IVORY 원본임을 명시한다.
- 제품과 조작부는 모바일 viewport의 가시 폭 안에 있다. 의도된 왼쪽 01 돌출, 네비게이션·섹션 순서, 색 방향은 유지됐다. 브라우저 콘솔 오류는 관찰되지 않았다.

## 정직한 한계
이것은 새 자산을 반영하는 한 페이지의 수정 과제 1회씩이다. 두 Harness의 일반적 동등성이나 새 디자인을 처음부터 만드는 능력, 사용자 만족을 증명하지 않는다. 모바일 크기에서 마우스로 조작했으며 실제 터치 기기의 촉감·성능은 확인하지 않았다. 이미지 자체는 평가용 생성 자산이다. 미적 평가는 관찰한 장면에 대한 비판적 판단이며 사용자 수용으로 대체할 수 없다.

실험 결과는 **개선 버전을 승격하거나 설치본을 바꿀 근거가 부족하다**는 것이다. 추가 규칙이 특히 필요하다고 주장한 상황에서도 A가 같은 문제를 해결했다. 다음 수정은 새 문서를 더하는 것보다, 개선 버전만 실패를 줄일 수 있는 실제 실패 유형과 판별 기준을 먼저 찾아야 한다.
