### 현행 예방·탐지·복구의 빈틈

- 예방: 고정한 원본·타깃·검사·입력·캡처로 낡은 결과를 막는다. 이 안전 경계는 유지한다.
- 탐지: `load_baseline`은 authority 파일 전체 바이트, `input_fingerprint`는 입력 파일
  전체 바이트를 비교한다. 무엇이 바뀌었고 어떤 규칙/화면에 영향을 주는지 설명하지 않는다.
- 복구: 독립 기준 검토→새 pin→넓은 재관찰에 의존한다. JOENESS의 기존
  `--previous-baseline`도 shared authority/targets/rules가 바뀌면 재사용하지 않는다.
  문서에 재사용 가능성이 언급돼 있다는 사실을 정밀 재사용 구현으로 해석하지 않는다.
- 원인 가설: 안전성을 파일 경계에 맞춘 계약과 영향 근거 생산 수단의 부재가 비용을 만든다.
  이를 단순 에이전트 실수로 종결하지 않는다. 실제 시간 절감량은 아직 측정하지 않았다.

### 보강 항목과 사용자 흐름

1. **읽기 전용 영향 보고부터 구현한다.** 이전/현재 원본·기준·입력·결과를 받아
   변경 규칙, 검사, 화면·상태, 영향 근거, 미상 원인과 다음 조치를 한 번에 제시한다.
   초기 결과는 재사용 *후보*이며 기존 gate를 자동으로 통과시키지 않는다.
2. **원본 규칙의 대응을 명시한다.** 원문 위치·내용·적용 범위·상속하는 공통 규칙을
   연결한다. 안정 ID만 같거나 부분 문자열 해시만 같다고 의미 불변으로 보지 않는다.
   규칙 삭제·완화·예외 추가·적용 대상 축소는 별도 승인/기준 검토 대상으로 드러낸다.
   문서 전체 원본 해시와 변경 이력도 보존한다.
3. **재사용 계약을 공동 구현한다.** JOEDESIGN은 검사별 `영향 없음 근거 있음` /
   `관련 변경` / `영향 미상`을 생산하고, 독립 검토된 전환 근거에 연결한다.
   JOENESS는 별도로 고정한 이전/현재 계약과 identity/freshness/coverage를 검증한다.
   단순 생산자의 `unaffected:true` 주장이나 현재 receipt의 pin을 신뢰하지 않는다.
4. **CSS 정밀도는 증거 범위만 연다.** selector 문자열 diff만으로 재사용하지 않는다.
   cascade, specificity/order, 상속, custom property, reset, 미디어/컨테이너 조건,
   폰트/자산/DOM/동적 클래스 및 늦게 로딩되는 의존성까지 영향을 검토해야 한다.
   파서/수집 방식과 지원 범위는 계약 검토에서 정하며 무단 새 런타임 의존성을 추가하지 않는다.
   지원하지 않는 문법·조건·관찰하지 못한 의존성은 미상으로 남겨 기존 fresh 검사를 유지한다.
5. **결과를 고치지 않고 새 전환 기록을 남긴다.** 이전 기준·실패 결과·캡처는 불변.
   새 결과는 어떤 이전 검사를 어떤 검토 근거로 재사용했는지, 새로 관찰한 것은 무엇인지
   구분한다. 전달 중 실패하면 기존 근거를 보존하고 미완료 전환만 재개한다.

사용자에게 machine JSON 작성이나 매번 동일한51개 수동 검토를 떠넘기지 않는다.
“재사용 후보 N / 재관찰 N / 영향 미상 N — 이유와 필요한 조치”를 먼저 보여주되,
합계가 필수 검사 전체와 일치하고 대상 누락이 없음을 기계적으로 확인한다.
관찰하지 않은 새 빌드의 시각 결과를 과거 캡처로 가장하지 않는다.

| 공유 토큰·상속·cascade/order 변경 | 영향 검사 무효화. 동일 selector 또는 DOM만 같아도 통과시키지 않음 |
| 기준 완화·규칙/대상 삭제·공통 예외 추가 | 권한/기준 재검토를 요구하고 누락된 필수 coverage 차단 |
| lazy/conditional 모듈·폰트·자산·서버 제공 빌드 변화 | 관련 검사 fresh; 대응·완전성 입증 불가 시 영향 미상. 요청 목록만으로 전체 의존성 완전하다고 주장하지 않음 |
| 과거 캡처 변조·다른 route/state/viewport·소비 계약 불일치 | 재사용 차단; 과거 실패 및 사용자 반려 보존 |
| 일부 새 관찰 실패·중단 후 재개·겹치는 old/new 검사 | 실패/미확인 유지, 중복·빠진 항목 차단; 무관한 독립 완료는 유지 |

완료는 생산자 단독 unit test로 판정하지 않는다. JOEDESIGN 실제 영향 보고→JOENESS
실제 소비 CLI까지 연결해 위 양성/음성 사례를 검증하고, Manager가 소유 경계를 대조한다.
그 뒤 허용된 실제 변경 사례에서 재관찰 수·도구 호출·수동 판단·소요 시간을 기존 방식과
비교한다. 무관 변경의 비용 감소와 관련 변경 누락 없음이 함께 확인돼야 실사용 보강으로
보고한다. 일부 CSS 경우가 미상이면 지원 범위를 제한해 보고하고 전면 해결이라고 하지 않는다.

## F02 — 납품 상태와 디자인 판정의 연결

### 근거와 빈틈

GEO ROADMAP은 2026-10-13 데모 제작 마감, 운영/실검색 범위 밖,
실제PC200%·음성·5인 조사 등 미검증 보존을 명시한다. state31의
`READY_FOR_REVIEW/UNAPPROVED`와 `demo-closeout-checks.json`의 문서 정합 통과도
직접 확인했다. 제품 마감이 전체 Manifest 승인이나 미검증 PASS를 뜻하지 않는다.

현재 코어는 기술·시각·workflow·사용자 수락 분리를 요구하고, 생산자는 acceptance를
`NOT_GRANTED`로 유지한다. JOENESS는 scoped claim과 required_acceptance를 검사한다.
하지만 나열한 한계가 **이번 납품의 필수 잔여인지**, 다른 범위의 미검증인지를
통합해서 설명하는 일은 담당자의 문장 작성에 남아 있다. 거짓 완료 방지 규칙은 있으나
불필요한 완료 유예와 사용자 혼동을 예방·탐지·복구하는 지원이 약하다.

### 보강과 접점

- JOEFLOW가 현행 납품 범위와 결정/승인 출처를 제공한다. JOENESS가 최종 통합 표시를
  소유한다. JOEDESIGN은 판정을 임의 완화하지 않고 다음 원천 자료를 짧게 제공한다:
  평가한 출력·화면/상태·시점, 기술 관찰, 시각 준수/품질 판단, 정확한 수락/반려 출처,
  해당 범위 필수 실패·미확인, 적용하지 않은 범위와 알려진 한계, stale 여부.
- 첫 화면/첫 보고는 **현재 납품 상태 / 반드시 남은 일 / 범위 밖 / 참고 미검증**으로
  구성한다. 긴 상세 이력은 기존 증거로 연결한다. 새 작업 원장이나 병렬 DESIGN 승인장을
  만들지 않는다. `REVIEW_COMPLETE_UNCERTIFIED` 같은 내부 상태만으로 답을 끝내지 않는다.
- 수락의 부재, 명시적 반려, 일부 범위 수락을 구별한다. 제작을 마감하라는 지시를
  모든 화면에 대한 정확한 시각 수락으로 바꾸지 않는다. 기존 required_acceptance를
  자동 false로 만들거나 현재 반려를 범위 밖으로 밀어내지 않는다.
- 필수 여부가 상충하거나 근거가 없으면 영향 범위만 `판단 필요`로 표시한다.
  사용자 결정을 추측하지 않고 어느 출처·소유자의 판단이 필요한지 특정한다.
  Manager는 충돌을 조정하되 제품 의미/디자인 판정/사용자 승인 원본을 덮지 않는다.

### 검증과 완료 기준

| 사례 | 기대 사용자 요약 |
|---|---|
| 사용자 범위가 비런칭 데모로 확정, 해당 필수 작업 완료, 운영검사 보류 | 데모 제작 마감. 운영은 범위 밖·미검증 유지. 전체 Manifest 승인으로 바꾸지 않음 |
| 기술 일부 PASS, 현재 필수 화면에 사용자 반려 | 해당 납품 미완료, 반려 대상과 재작업을 선명히 표시. PASS 수로 덮지 않음 |
| 과거 필수 과제가 현행 승인 범위에서 제외 | 현재 남은 일에서 제외하되 범위변경 출처/이력 보존. 과거 실패는 삭제하지 않음 |
| 현재 필수 시각검사 실패·누락·stale | 관련 범위 완료 차단; 무관한 납품/구현 완료까지 취소하지 않음 |
| 범위 미상·상충, 일부 화면만 수락 | 판단 필요와 정확한 미확정 범위를 표시; 전체수락 또는 무한 대기로 단순화하지 않음 |

JOEDESIGN 출력과 JOENESS 실제 요약을 연결한 시험에서 상태를 정확히 보존하고,
새 문맥의 담당자가 “무엇이 끝났고 반드시 무엇을 해야 하는지”를 오인하지 않는지 확인한다.
오판한 요약과 수정 이력을 보존한다. 사용자 시각 수락은 이 시험 에이전트가 대신하지 않는다.
