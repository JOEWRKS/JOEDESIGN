## 변경 전 범위와 검증 기준

JOENESS, JOEFLOW, 과거 증거는 수정하지 않는다. 커밋·푸시는 보류한다.

변경 전에 다음 검토 기준을 고정했다. 아래 상황은 문서의 정합성 검토용이며
실제 모델 행동·브라우저 관찰·사용자 테스트 결과가 아니다.

1. 모든 정보가 있지만 부수 안내가 반복되어 핵심을 압도하는 화면:
   정보 존재와 정보 위계를 따로 검토하고, 실제 넓은/좁은 화면의 관찰을 요구한다.
   안내 상자나 반복 자체를 일괄 금지하지 않고 필수 안전·오류 안내를 보존한다.
2. Product 문서에 필수 제약·제안 수치·승인 수치가 혼재:
   출처·승인 범위를 확인한다. 승인된 수치를 임의로 제안으로 낮추지 않는다.
   제품 의미/노출조건은 Product, 시각 제안은 디자인 담당이 처리하며 충돌 없는 작업은 계속한다.
3. DESIGN.md에 승인 이력만 있고 구현 역할이 흩어진 프로젝트:
   디자인 담당이 필요한 컬러칩/조합, 타이포 크기·굵기·행간, 위계별 여백,
   공통 컴포넌트/상태를 기존 루트 문서와 네이티브 역할에 연결한다.
   구현값·제안·승인을 구분하고 새 문서·전면 토큰표를 강제하지 않는다.
4. 최신 기획과 실제 소비한 기획 버전이 다르거나 화면 관찰이 없는 경우:
   적용 완료나 시각 PASS로 보고하지 않는다. 무관한 전면 감사로 확대하지 않는다.
