# Quality repair after the rejected BIO/02 proof

Historical experiment record. As of 2026-09-30, these runtime corrections match the
existing installed Harness and are retained in repository source. Rendered design
improvement remains **UNVERIFIED**. The original scope and observations below describe
the correction when it was a source candidate; they are not evidence of later quality.

## Trigger and scope

The user rejected the system-focus.html output as visually inadequate and a poor
translation of Dala. Earlier static-review disposition and technical test results
did not establish user acceptance or the required visual quality. Treat that output
as rejected, not as a positive quality example or a calibrated design benchmark.

User feedback in the current conversation is the basis for this rejection record.
No synthetic host acceptance/rejection receipt was created for the actual BIO proof.
The prior BIO files and earlier evidence remain unchanged. The candidate changes
only joedesign-harness and its tests/docs; frozen joedesign v0.2, JOENESS, JOEFLOW and
installed skills are unchanged. This is not a global deployment.

## Corrections

- Production guidance now starts with the dominant visual risk, actual source frames
  and motion observations, a deliberate focal-asset production choice, and a finished
  key scene/transition before broad construction. Repairs must target the observed
  cause: asset production, composition, temporal beats or local craft.
- Synthesis bundles route to that guidance. Critic bundles request whole-screen
  comparisons and actual sequences, separate from functional/contract checks.
- Expansion previously required structural PASS and complete captures but did not
  require visual PASS. It now also requires VisualInternal PASS, a current Critic,
  and remaining categories passing. Failed or unverified visual quality blocks it.
- Visual claims previously only accepted render evidence. A declared motion
  translation now requires additional required VisualConformance and VisualQuality
  interaction claims for each applicable target, linked to that translation.
  Whole-screen render review remains required; unrelated/optional motion claims do
  not substitute for this coverage.
- Authenticated exact user rejection now yields REJECTED and material rework even
  when internal checks pass. It is no longer flattened to PENDING.

## Verification

Eight new regression cases were run against the previous implementation and all
eight failed, reproducing missing policy or unsupported motion-review coverage.
After the changes, all passed.

- Python suite: **69 tests passed** (61 existing + 8 added).
- Preserved v0.2 Node suite: **14 tests passed**.
- The core package byte-preservation test passed.
- New reference resolves from a project-local package copy.

These are executable policy/packaging checks with synthetic receipts, not a model
behavior trial, visual A/B or live proof that the system makes better designs.
No new BIO render was produced in this correction. The generic critic remains
uncalibrated and the CLI still has no authenticated host adapter; local automatic
certification/expansion remains unavailable. Authorized bounded production work
can continue and be presented honestly without automated certification.

## What would establish improvement

Use the revised production guidance on a newly authorized bounded design attempt.
Retain the rejected candidate and inspect actual primary-source/result compositions
and sequences. Evaluate whether the dominant visual gap is reduced, not only whether
small defects or accessibility issues were repaired. Report functional checks,
visual judgment and the user's response separately. An unchanged weak composition
with more documentation or a new PASS label is not improvement.
