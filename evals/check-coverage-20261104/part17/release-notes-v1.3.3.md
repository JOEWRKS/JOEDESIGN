## 1.3.3 — R7 탐지 범위 확장: 줄마다 판정, `--inject` 문장 (2026-11-18, T043)

16부 행동 A/B(주입 미언급 장면)에서 1.3.0 팔의 거짓 `rendered`(주입해 잰 줄에 괄호 없는 `rendered`) 4건 중 1.3.2 R7이 잡은 것은 2건이었다. 놓친 두 형태(일부 줄에만 주입 표시가 있는 보고, `--inject`와 css 낱말이 먼 문장)를 스크립트로 막는다. 스키마·계약·CLI·도장 형식·`--verify` 종료 코드 의미는 그대로다.

- **주입 인식**: 문장에 부정되지 않은 주입 낱말(주입, inject(ed), `--inject` 명령·코드 블록 안 포함)과 CSS 낱말(css, 스타일, style, stylesheet)이 함께 있으면, 또는 "style.css를 넣어 쟀다"처럼 CSS를 넣었다는 표현이면 보고가 주입을 말한 것으로 본다. "200자를 넣어" 같은 무관한 "넣어"는 아니다.
- **줄마다 판정**: 그런 보고에서 넷째 칸이 정확히 `rendered`인 결과 줄은 각각 R7로 지적한다(어느 측정인지 알 수 없기 때문). `rendered (own css)`로 적었거나, 목록 밖 문장이 그 검사 이름을 들어 페이지가 자기 CSS를 읽었다고 말하면 통과.
- `templates/DESIGN.md` 측정 모드 문단과 `references/conformance.md` R7 설명 한 줄씩.

**확인된 것**([17부 보고](https://github.com/JOEWRKS/JOEDESIGN/blob/main/evals/check-coverage-20261104/part17/report.md)): 16부 A의 거짓 `rendered` 4건 모두 R7(1.3.2 2/4 → 4/4). 16부 B 4건, 14부 B 16건, 15부 도장 보고 중 1.3.2 `text ok` 42건에 새 R7 0. 기존 evals 보고 274개의 R1~R6 지적 수는 1.3.2와 같고 R7 0 → 0. 테스트 node 41/41(report-check 23 → 27), python 142 OK.
