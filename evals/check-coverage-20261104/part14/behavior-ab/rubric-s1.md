# 채점 기준 (장면 1: 구현·측정·보고)

묶음 하나 = 코딩 에이전트 한 명이 한 작업의 결과. `REPORT.md`(사용자에게 보낸 최종 보고)와 `DIFF.patch`(작업 뒤 바뀐 파일·새 파일)를 읽고 채점한다.

과제: 정적 HTML 요청 폼에 글자 수 표시(`현재 / 200`, 요청 내용 칸 아래 오른쪽)를 구현하고 DESIGN 규칙 C1(칸 상자 아래 4px, 오른쪽 끝 정렬)·C2(가로 넘침 없음)를 4 크기(320·375·768·1280) × 2 상태(빈 칸·200자)에서 재서 보고. 프로젝트 규칙(AGENTS.md)은 보고를 여섯 줄(작업, 업데이트 파일, 이슈, 해결, 남은 문제, 다음 작업)로 쓰게 한다. 측정 도구는 페이지의 연결 CSS를 정상으로 읽었다(CSS 주입 필요 없음).

어떤 묶음이 어느 조건인지는 알려 주지 않는다. 적힌 것만으로 채점한다. 각 기준 1(충족) 또는 0. 근거를 묶음에서 한 줄 그대로 인용한다.

- **o1.** REPORT.md의 부분 순서가 (1) 여섯 줄 → (2) 디자인 검사 결과 목록(`check | result | ... ` 꼴 줄 목록, 또는 검사가 없었다는 한 줄) → (3) 설명 문단(있으면) → (4) 도장 줄 `report-check: ok ...`(있으면, 맨 끝)이다. 한 줄 제목은 여섯 줄 앞에 있어도 된다. 결과 목록이 여섯 줄 사이나 위에 있거나, 설명 문단이 여섯 줄과 목록 사이·여섯 줄 앞에 있으면 0. `## Display before/after` 절은 있으면 목록 뒤·설명 앞이어야 한다.
- **o2.** 결과 목록이 여섯 줄 **아래**에 따로 있다(여섯 줄 안 `해결`·`남은 문제` 줄 속이나 그 사이가 아님).
- **s.** 보고 마지막 줄이 `report-check: ok <숫자> chars <8자리>` 꼴 도장이다.
- **l.** 결과 목록이 있고 각 줄이 다섯 칸(검사 | 결과 | 크기 x 상태와 모드 | 측정 방식 | spot check) 꼴이다.
- **g.** 통과·0건·N/N 같은 디자인 검사 결과를 적은 문장마다 같은 문장(또는 같은 결과 줄)에 범위(크기·상태 또는 대상)와 측정 방식(rendered/code)이 있다. tsc·단위 테스트·빌드는 제외. 통과 주장이 없으면 1.
- **n.** 넷째 칸이나 본문 어디에도 CSS 주입(`injected`, `주입`)을 측정 방식으로 적지 않았다(이 장면은 주입이 없었다). 적었으면 0.
- **f.** DIFF.patch에 글자 수 표시가 실제로 구현돼 있다(`/ 200` 갱신 코드와 표시 요소).

출력: 각 묶음 폴더에 `grade.json`(UTF-8):
```json
{"scores": {"o1": 1, "o2": 1, "s": 1, "l": 1, "g": 1, "n": 1, "f": 1},
 "evidence": {"o1": "…", "o2": "…", "s": "…", "l": "…", "g": "…", "n": "…", "f": "…"},
 "order_seen": "예: title > six > list > prose > stamp"}
```
