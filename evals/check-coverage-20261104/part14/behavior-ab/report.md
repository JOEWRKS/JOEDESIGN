사전 등록: [plan.md](plan.md)(커밋 c76aff9, 실행 전), 프롬프트 [prompt.md](prompt.md), 채점 기준 [rubric-s1.md](rubric-s1.md)·[rubric-s2.md](rubric-s2.md). 원문: [runs/](runs/)(REPORT.md, DIFF.patch), 채점: [blind-grades/](blind-grades/), 합본 [grades.json](grades.json), 기계 측정 [mech.json](mech.json), 집계 [summary.txt](summary.txt)(`collect.py` → `summarize.py`), 배치표 [blind-map.json](blind-map.json)(채점 뒤 복사), 사고 [incidents.txt](incidents.txt).

## 오탐·회귀

- 오탐: 연결 CSS가 정상인 장면 1에서 `injected` 표기 0/16(두 팔). R6·R7은 B 16개 보고에서 지적 0, 자기 팔 `--verify` 32/32 통과.
- 회귀: B가 A보다 낮은 항목 없음. 1.3.1 문구가 늘린 SKILL.md 554바이트로 다른 항목(결과 목록, 다섯 칸, 도장, 구현)이 떨어지지 않았다(16/16 유지).
- 두 팔 공통으로 C1 간격을 상자 4px vs 보이는 7~9px로 나눠 통과로 적지 않은 run이 28/32. 통과(complete)로 적은 run은 A t14(상자 기준만 대조) 1건, 결과는 맞다고만 적고 pending으로 둔 run 3건.

## 확인된 것 / 확인되지 않은 것

확인된 것
- 배치 순서 규칙(1.3.1 Report Form)은 행동을 바꾼다: 순서 준수 B 16/16 vs A 7/16(두 장면 합). A의 주된 실패는 여섯 줄 앞 요약 문단이다.
- `rendered (injected css)` 표기와 R7: B 8/8 정확, R7 0. A는 6/8이 스스로 같은 표기를 썼고, 2/8은 주입을 셋째 칸에 적어 R7에 걸렸다.
- 오탐 0(정상 CSS 장면에서 주입 표기 0/16), 퇴행 없음.

확인되지 않은 것
- 표기 개선의 크기: 6/8 vs 8/8은 사전 기준(차이 3 이상)에 못 미친다. 과제 자료가 "주입"을 직접 말하지 않는 상황(에이전트가 `loaded:false`만 보고 알아채야 하는 경우)은 시험하지 않았다(추가 필요).
- R6가 잡지 못하는 배치 위반(여섯 줄 앞 요약 문단, 여섯 줄과 목록 사이 문단): A 실패 9건 중 8건이 여기 해당. B는 0건이라 문서만으로 지켜졌지만 스크립트 보장은 없다.
- 장기(여러 턴)·인계 세션·Codex 환경의 행동. 한 턴 Opus, 고정물 한 종류뿐.
- JOENESS 쪽 소비(이 시험은 JOENESS 연결 문구만 넣었고 JOENESS 스크립트는 돌리지 않음).
- 실행 에이전트 다수가 공용 임시 폴더에 보조 파일을 써 run 간 격리가 완전하지 않았다(incidents.txt 1). 보고와 채점 묶음은 섞이지 않았다.
