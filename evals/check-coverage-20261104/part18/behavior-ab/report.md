## 반사실 검사: 허용 문장 경로 (유료 실행 0회)

네 run이 모두 `(own css)`를 써서, 괄호 없는 `rendered` index 줄을 R7이 어떻게 다루는지는 행동으로 나오지 않았다. 그래서 실물 보고를 고쳐 1.3.3 report-check(도장 없는 검사)에 다시 넣었다. 기준은 블라인드가 "올바르다"고 본 보고다. 괄호 없는 `rendered`는 템플릿 뜻으로 자기 CSS이므로, 그렇게 고친 보고도 측정 모드는 맞다.

- A: 결과 줄 넷째 칸 `rendered (own css)`만 `rendered`로 바꿈. 본문은 그대로.
- B: A에 더해, 본문 괄호 속 `rendered (own css)`·`own css` 반복 표기를 지움. 에이전트가 넷째 칸을 괄호 없이 썼다면 본문에서도 그 말을 되풀이하지 않았으리라는 가정이다.

| run | 괄호 없는 index 줄 | A R7 | B R7 | 원인 |
| --- | --- | --- | --- | --- |
| r01 | 3 | 3 | 3 | 허용 문장 "요청 화면은 자기 링크 CSS를 읽었다(loaded=true)."에 검사 이름(`C1`, `C2`, `AC-002`)이 없음 |
| r02 | 3 | 0 | 0 | B도 통과. 다만 넘긴 근거는 **확인 화면** 문장이다: "확인 화면을 자체 CSS로 여는 측정 방법이 생기면 C1·C2를 확인 화면에서 다시 잰다". 부정 낱말이 없고 `자체 CSS`와 `C1·C2`가 함께 있어서 허용 문장으로 셌다. 결과는 맞지만 근거가 틀렸다(잘못 넘어감). |
| r03 | 2 | 0 | 2 | A는 본문 괄호 속 "rendered: 요청 화면 own css"로 넘어감. B에서는 남은 자기 CSS 문장이 "확인 화면 자기 CSS 렌더 측정 방법도 소유자가 정한다"뿐이고 검사 이름이 없음 |
| r04 | 4 | 2 | 4 | A: C1 두 줄은 넘어감. C2 줄은 허용 문장 안 "캡처 **마지막** 잉크 열"의 `막`이 부정어(`OWN_CSS_NOT`의 `막`)로 잡혀 무효. AC-002 줄은 같은 문장 안 "not spot-checked"의 `not`이 부정어로 잡혀 무효 |

B 기준으로 올바른 보고 4개 중 3개(r01, r03, r04)가 R7에 걸린다. 반사실 오탐 3/4. 나머지 1개(r02)는 엉뚱한 페이지 문장 때문에 통과한다.

허용 경로가 부족한 곳(이번 실물에서 나온 것):
1. **검사 이름 요구.** 사람이 쓰는 자연스러운 허용 문장은 페이지를 이름으로 든다("요청 화면은 자기 링크 CSS를 읽었다"). 검사 이름 첫 낱말(`C1`)은 들지 않는다. 이 장면처럼 같은 검사 이름(C1, C2)이 두 페이지에 걸치면 검사 이름은 페이지를 가르지 못한다. 반대로 확인 화면 문장도 index C1 줄을 넘긴다(r02).
2. **부정어 부분 일치.** `OWN_CSS_NOT`의 `막`은 `마지막` 안에서도 맞는다. `\bnot\b`는 템플릿 자체의 어휘 `not spot-checked`에 맞는다. 결과 줄 문법을 본문 괄호에 되풀이하는 보고(1.3.x 보고 양식이 권하는 형태)에서는 거의 늘 걸린다.
3. **문장 단위.** 한 문장이 두 페이지를 함께 말하면("요청 화면 own css, 확인 화면 injected css") 다른 페이지 쪽 부정어가 허용을 지운다. `막아`, `못했다`, `blocked`가 그런 예다.

에이전트가 `(own css)`를 줄 안에 쓰면 이 문제들은 모두 피한다. 이번 4/4가 그랬다.

## 확인된 것

- 1.3.3은 이 장면의 올바른 보고 4/4를 통과시켰다. R7 오탐 0, `--verify` 4/4, 다른 지적 0.
- 에이전트는 과제 자료에 주입 설명이 없어도 페이지별로 측정 모드를 갈라 적었다. index는 `rendered (own css)`, confirm은 `rendered (injected css)`이고 4/4가 정확했다. 거짓 `rendered` 0.
- 허용 경로로는 줄 안 `rendered (own css)`만 쓰였다(4/4). 네 run 모두 작성 중에 R7을 한 번도 만나지 않았다. 지적을 받고 고친 것이 아니라 처음부터 그렇게 썼다.
- 반사실: 목록 밖 문장 허용 경로는 실물 보고에서 약하다. 올바른 보고 3/4가 걸리고, 1/4은 다른 페이지 문장으로 잘못 넘어간다. 구체 원인은 셋이다. 검사 이름 요구, `막`·`not` 부분 일치(`마지막`, `not spot-checked`), 두 페이지를 함께 말하는 문장이다.

## 확인되지 않은 것

- 괄호 없는 `rendered`를 쓰는 에이전트 행동. 0/4라 실제로 그렇게 쓴 보고의 R7 결과는 반사실로만 봤다. B 변형("본문에서도 own css 표기를 지움")은 가정이다.
- 에이전트가 `(own css)`를 쓴 이유. 템플릿 측정 모드 문단과 report-check 머리 주석에 그 형식이 있다(r01·r03은 R7 설명을 직접 읽음). 어느 문서 때문인지는 나누지 않았다.
- 표본 크기: 4회, 한 턴 Opus, 고정물 한 종류(두 페이지가 같은 CSS 공유, 검사 이름이 두 페이지에 걸침). 페이지마다 검사 이름이 다른 보고, CSS가 다른 페이지, 다른 모델·Codex는 시험하지 않았다.
- 반사실에서 찾은 문제(`막`·`not` 부분 일치 등)는 이번 과제 범위 밖이라 고치지 않았다. 고칠지와 고치는 방법은 따로 정한다.
