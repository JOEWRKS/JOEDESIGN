### 2.9 다크 모드 (rev 27)

`prefers-color-scheme: dark`일 때 `src/tokens.css`의 색 토큰만 덮어쓴다(`color-scheme: dark` 포함). 앱 안 전환 버튼은 없다. 쓰려고 먼저 역할을 나눴다: `--ink`는 외곽선·그림자·밝은 채움 위 글자, `--text`는 종이·바탕 위 글자. 이전에 직접 적혀 있던 글자·바탕 색 13가지도 토큰으로 바꿨다(밝은 모드 값은 그대로).

## 4. 화면 규칙

1. **한 화면.** 1440×900·390×844에서 페이지 스크롤이 없다(`100dvh`, body `overflow: hidden`). 높이가 모자라면 말풍선 칸 안에서 덜 중요한 것부터 접는다: 내 수 설명 → 카드 설명 → 보조 줄 → 큰 숫자 크기 → 제목·경고(칸 높이 520 / 420 / 330 / 250 / 190 단계), 160 이하에서는 후보 알약 줄(같은 후보가 판 위 숫자로 보임), 120 이하에서는 큰 숫자를 30px로(rev 23). 말풍선 칸 폭이 560 이상(세로 태블릿)이면 큰 숫자를 48·44로 줄이고, 칸 높이 265–420에서는 설명 문장 한 줄을 접지 않는다(rev 28). 판과 주 버튼은 접지 않는다.
2. **배치.** 폭 900 이상이면서 가로:세로 5:4 이상이면 판(왼쪽, 높이 기준 최대) + 옆 칸(위 말풍선, 아래 버튼). 나머지는 세로로 대결줄 → 판 → 말풍선 → 버튼. 판 크기는 버튼 높이, 말풍선 최소 높이(160 / 210 / 280, 화면 높이별), 판 그림자 높이를 먼저 뺀 나머지다. **휴대폰 가로(rev 34, 가로이면서 높이 500 이하):** 휴대폰 값(글자·간격 "폭 700 이하" 열·44px·상단 줄 52)을 쓰고, 판(왼쪽, 높이 기준) + 옆 칸(`clamp(280px, 46vw, 420px)`, 위 말풍선·아래 버튼) 배치. 시작 화면은 로고 글자 28px·빈 안내 줄 숨김, 도움말 창은 두 단(왼쪽 규칙 목록, 오른쪽 상자), 복기 바는 상단 줄 첫 칸(상단 줄 62).
3. **시선 순서.** ① 판과 기준 표식 ② 말풍선의 좌표·승률 큰 숫자 ③ 주 버튼 ④ 다른 후보 알약·상대 예상 ⑤ 고지문·스위치.
4. **판 위 표식.** 색만으로 구별하지 않는다. 모양·숫자·투명도를 함께 쓴다.

   | 표식 | 모양 |
   | --- | --- |
   | 실제 돌 | 불투명, 실선 외곽선 + 그림자 |
   | 추천(1위) | lime 35% 채움 + lime-dark 점선 + 승률 숫자 |
   | 다른 후보 | 흰 25% + ink 점선 + 숫자 |
   | 착수 예정 | 돌보다 큰 sun-dark 굵은 점선 고리(회전) + 안쪽 sun 45% 승률 |
   | 상대 예상 수 | 상대 색 돌, 불투명도 0.5, 실선 + 번호(rev 20 예외) |
   | 내 예상 수 | 점선 고리 + 번호 |
   | 금수 | pink 점선 고리 + ✕ |
   | 마지막 수 / 승리선 | 돌 가운데 pink 점 / sun 굵은 고리 + ink 바깥 고리 |

5. **두께와 입체.** 굵은 ink 외곽선과 흐림 없는 그림자는 누를 수 있는 것과 떠 있는 표면에만 쓴다. 판 위 가상 표식은 그림자 없이 점선이다.
6. **숫자와 고지.** 승률(%)은 가이드가 켜져 있을 때 "엔진 추정 승률 · 실제 승률 아님" 고지와 같은 화면에 둔다.
7. **버튼.** 행동 버튼 높이 44 이상(주 버튼 76 / 60). 휴대폰(폭 700 이하)에서는 보조 버튼을 포함해 누르는 것 모두 44×44 이상이다(rev 23, 사용자 지시): 아이콘 버튼 44, 작은 버튼·후보 알약·선택지·스위치·글자 버튼 최소 44, 복기 바 안 버튼 44. 같은 줄 버튼은 높이와 그림자 끝이 같고, 되돌리기는 상태와 관계없이 같은 폭이다. **예외: 판 교차점**은 15×15칸이라 휴대폰에서 약 22–24px이고 44px로 키울 수 없다. "한 번 눌러 예정, 한 번 더 눌러 착수, 취소"로 보완한다.
8. **포커스.** ink 3px 외곽선(간격 3, 교차점은 안쪽 -2). 판은 tab stop 1개 + 방향키.
9. **대비.** 글자 4.5:1(24px 이상 또는 굵은 18.66px 이상은 3:1), 상태를 알리는 그래픽 3:1을 목표로 한다. 외곽선 글자(로고·브랜드·승률 숫자)는 채움색이 아니라 ink 외곽선과 바탕의 대비로 읽히며, 판정은 전문 검토가 필요하다. 현재 미달은 §6.
10. **확장.** 새 화면·상태는 위 토큰과 구성요소를 다시 쓴다. 새 색·크기·그림자가 필요하면 이 문서에 역할을 먼저 적고 사용자 확인을 받는다.
11. **복기 화면(rev 22).** 복기 이동은 화면 맨 위 상단 바 하나에 모은다. 옆 배치에서는 상단 줄 가운데(대결줄 자리, 복기 중 대결줄은 숨김), 세로 배치에서는 상단 줄 둘째 줄에 판과 같은 폭(최대 680)으로 두고, 바 그림자 끝 → 판 위 = `--gap-block`. 말풍선 칸에는 당시 해설 카드만 남는다. 키보드 순서는 이전 → 다음 → 종료 판으로 → 판. 세로 배치에서는 바 높이(넓은 화면 50, 휴대폰 58)만큼 판이 작아진다(rev 22 측정: 390×844 366 → 약 360px, 768×1024 약 548 → 444px, 360×640 270 → 약 210px. rev 23에서 휴대폰 바가 8px 높아져 조금 더 작아짐).
12. **테마(rev 27).** 시스템 설정을 따른다. 새 색은 `tokens.css`의 밝은·다크 두 값으로 함께 정한다. 밝은 채움 위 글자는 `--ink`, 종이·바탕 위 글자는 `--text`를 쓴다. 판은 두 테마에서 같다.

#### 방향

초보자가 판과 한 문장 해설을 번갈아 보기 쉬운 차분한 학습용 바둑판. 큰 홍보 영역·장식 이미지·랭킹·승률 게이지는 두지 않는다. 페이지 이름은 “함께 배우는 AI 오목”, 보조 문구는 “한 수씩, 이유를 보며 배워요.”

#### 배치

- **1440×900:** 짧은 제목/규칙·새 게임 행 아래, 왼쪽 판 520px, 간격 50px, 오른쪽 설명 350px. 실제 화면 점검 후 기본 판과 주요 행동을 같은 화면에서 조작하기 쉽도록 초기 620px 제안보다 줄였다. 긴 해설은 세로 스크롤할 수 있다.
- **390×844:** 좌우 16px 여백, 제목 → 차례/짧은 안내 → 폭 358px 이내 판 → 선택 좌표/확정 버튼 → 추천·해설 순서. 긴 해설은 자연스러운 세로 스크롤. 판 폭을 줄여 모든 글을 억지로 한 화면에 넣지 않는다. 고정 하단 바가 판/버튼을 덮지 않도록 한다.
- 판은 정사각형. 외곽 교차점도 누를 수 있도록 내부 가장자리 여백과 좌표 영역을 둔다. 열 A–O(중간 문자 생략 없음), 행 1–15, 위에서 아래로 증가. 좌상단 A1, 중심 H8. 화면·검사·해설 모두 이 기준을 공유한다.
- “현재 추천”과 “직전 수 해설”을 제목으로 분리한다. 예상 수가 있는 검토 중에는 그 판을 그대로 유지한다. 다음 판으로 넘어가면 이전 예상 고리는 지우고 직전 수 글만 출처 수와 함께 남긴다.

#### 상호작용 표현

- 종료 후 복기는 판 위의 `대국 복기`로 진입하고 같은 영역의 `이전 수 / 다음 수 / 종료 판으로`를 사용한다. `복기 중`과 표시 중인 수·색·좌표, 실제 종료 결과·총 수를 함께 표시한다. 설명 카드는 선택한 수에 해당하는 당시 해설과 기준 수를 보여주고, 기존 직전 내 수 카드·추천/예상 고리는 숨긴다. 작은 점과 승리선은 표시 중인 판에만 적용한다. 복기 중 되돌리기는 비활성화하고 종료 판으로 복귀하면 다시 사용할 수 있다. 새 게임 버튼은 계속 사용 가능하다. 시각 승인 여부와 실제 검사 근거는 [복기 기록](TASK.md#replay)을 따른다.

- 후속 승인 범위인 되돌리기는 착수 버튼 옆의 `↶ 되돌리기` 보조 버튼으로 제공한다. 두 버튼을 한 줄에 배치하고 데스크톱은 설명 오른쪽, 휴대폰은 설명 아래에 둔다. 키보드 순서는 착수 → 되돌리기다. 되돌릴 차례가 없거나 복원 분석 중이면 비활성화한다. 취소된 돌 수에 맞는 짧은 안내를 행동 영역과 live 알림에 표시한다. 이전 해설은 해당 수의 기준 표시와 함께 복원한다. 이 구성은 구현 선택이며 사용자 시각 승인으로 간주하지 않는다.

- 선택한 점은 돌을 놓기 전 좌표와 테두리로 보여준다. `H8에 두기` 버튼은 선택이 없으면 이유와 함께 비활성화한다. 일반 행동 버튼은 높이 44px 이상을 초기 목표로 둔다. 촘촘한 판의 교차점까지 모두 44px라고 주장하지 않는다.
- 컴퓨터에서 선택 가능한 교차점에 포인터를 올리면 배경이 강조된다. 별도 hover 좌표 미리보기는 없으며, 교차점을 선택한 뒤 행동 영역에 좌표가 표시된다. 터치는 hover에 의존하지 않는다. 한 번 누르면 선택, 다른 곳을 누르면 이동, 확정 버튼으로만 착수한다.
- 판은 키보드 한 번의 Tab 진입과 방향키 이동을 제공한다. 현재 점 1곳만 tab stop. Enter/Space는 선택, Tab으로 확정 버튼 이동. 점유된 점도 상태를 읽을 수 있으나 착수할 수 없다. 포커스는 보이고 화면 갱신 중 유지한다.
- 각 점은 “H8, 빈칸 / 흑 / 백”처럼 이름을 가진다. 차례·분석 완료·종료는 짧은 live 알림으로 전달하되 225칸을 매번 읽지 않는다.
- 마지막 착수에는 작은 중심 표식, 승리선에는 외곽 강조를 더한다. 추천·선택·예상·실제 돌이 겹치면 라벨과 모양을 유지한다.
- 분석 중 현재 카드 안에 “이 판을 살펴보는 중…” 표시. 실패 시 같은 카드에 재시도와 제한을 표시한다. 페이지 전체를 막는 로딩 화면이나 끝없는 spinner를 만들지 않는다.
- 동작 감소 설정에서 장식 전환을 제거한다. 애니메이션·소리·테마 전환은 초기 필수 범위가 아니다.

검증 기준과 현재 상태는 [ROADMAP의 U2](ROADMAP.md#p2)와 [V2](ROADMAP.md#p3)를 따른다. 구현 담당자의 시각 점검과 실제 사용자의 시각 승인/수락을 각각 기록한다.

### 사용자 시각 원칙 (2026-10-23, 사용자 지시)

v0.2 탈락 이유와 앞으로의 기준. 이 원칙은 사용자 지시이며 새 시각 방향의 판정 기준이다.

1. **게임처럼 보여야 한다.** 카드·제목·설명 문단을 쌓은 발표자료(PPT) 같은 화면이 아니다.
