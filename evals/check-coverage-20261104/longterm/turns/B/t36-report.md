네, 접힌 상태는 검사에 들어갑니다. 오히려 펼친 상태가 거의 빠져 있습니다.

**접힌 상태(기본)**
- 모든 화면 검사는 기본 상태인 접힌 상태에서 잽니다.
  - 간격 검사: 9크기 × 8상태
  - 복기 검사: 8크기
  - 토큰 검사: 1440·390, 밝은·다크 모드
  - 넘침 검사
- 접힌 상태에서 재는 것:
  - 말풍선이 넘쳐 잘리지 않는지(S4), 간격(SP)
  - 글자 12px 이상(S9)
  - 버튼이 휴대폰에서 44px 이상인지(S11). 이유 버튼도 버튼이라 여기에 포함됩니다.
  - 글자 대비(S10). 이유 버튼 글자도 포함됩니다.
- 이유 버튼만 따로 보는 규칙:
  - RT1: 접힌 상태에서, 이유 문장이 숨거나 잘렸을 때 버튼이 보이는지
  - RT3: 펼쳤다가 다시 누르면 접히는지
  - RT3 뒤에 다시 접힌 상태로 돌아와서 이어지는 화면들을 재기 때문에, 그 화면들도 접힌 상태 기준입니다.

**펼친 상태(검사 범위가 좁음)**
- 간격 검사의 후보 화면 하나에서, 9크기에 대해 RT2만 봅니다. 문장이 다 보이는지, 버튼이 말풍선 영역 안에 있는지입니다.
- 펼친 상태에서는 다음을 재지 않습니다.
  - 간격
  - 잘림. 펼친 상태는 말풍선 안 스크롤을 허용해서 따로 보지 않습니다.
  - 그림자·눌림·대비
- 복기와 끝난 판 화면에서 버튼을 펼치는 경우도 재지 않습니다.

마지막 결과는 직전 턴의 `npm run design:check -- --all`이고, 그 뒤 코드는 바뀌지 않았습니다. 이유 버튼 규칙 RT1~RT3는 9크기 모두 통과했고, 실패 24건은 기존 결함 DS-01·DS-05 때문입니다.

질문에 대한 답이라 파일은 바꾸지 않았습니다. 원하시면 펼친 상태도 간격·잘림·대비·눌림 검사에 넣겠습니다. 그러려면 펼친 상태에서 말풍선 안 스크롤을 허용할지 먼저 정해야 합니다.
