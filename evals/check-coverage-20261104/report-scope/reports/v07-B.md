간격 규칙을 정해 DESIGN.md에 적었고, `src/style.css`를 그 규칙에 맞췄고, `work/design/spacing-check.mjs` 검사를 추가했습니다. 다만 브라우저를 쓸 수 없어서 실제 화면에서 간격이 고르게 보이는지는 아직 확인하지 못했습니다. 그래서 이 문제(UI-05)는 열린 상태로 두었습니다.

- **작업:**
  - **원인 (코드 값으로 계산, 화면에서 잰 값 아님):** 말풍선 칸과 버튼 칸의 간격에서 부품마다 다른 아래 그림자(3~8px)가 그대로 깎이고, 일부 부품에는 개별 여백이 따로 붙어 있었습니다. 그래서 보이는 간격이 1px(버튼 줄 → 되돌리기 안내)부터 16px(금수 안내 → 버튼 줄)까지 달랐습니다. 같은 줄 버튼 사이(6~12px), 카드 안쪽 여백(7종), 판·말풍선 칸·버튼 칸 사이 간격(10~18px)도 값이 섞여 있었습니다.
  - **규칙 (제가 고른 제안값, 아직 승인 전):** 기본 간격은 4·8·12·16·24px 다섯 단계입니다.
    - 쌓인 카드·버튼 줄·안내 줄 사이는 모든 화면 크기에서 그림자 끝부터 8px입니다.
    - 같은 줄 버튼 사이는 8px입니다.
    - 카드 안쪽 여백은 주 카드, 보조 카드, 안내 줄 세 단계로 나눴습니다.
    - 판·말풍선 칸·버튼 칸 사이 간격은 위 다섯 단계 값만 씁니다.
    - 각 부품은 자기 그림자 깊이를 선언하고, 그 깊이만큼 아래를 더 띄우는 공통 규칙 하나로 처리합니다.
  - **검사 스크립트:** `src/style.css`의 화면 크기별 규칙까지 읽어 규칙 S0~S6을 검사합니다. `src/main.ts`에서 말풍선 칸·버튼 칸에 새 부품이 추가됐는데 규칙에 등록되지 않았으면 실패로 잡습니다.
  - **확인한 결과:**
    - 지금 CSS로 실행하면 S0~S6 모두 통과합니다.
    - `--self-test`로 규칙마다 일부러 어긋난 줄을 넣으면(8건) 해당 규칙만 실패합니다.
    - 바꾸기 전 CSS(HEAD)로 실행하면 7개 규칙 모두 실패하고 위반 73건이 나옵니다. 즉 원래 어긋남을 실제로 잡습니다.
    - 타입 검사 통과, 단위 테스트 87개 통과(1개는 원래부터 조건부 건너뜀), 빌드 성공입니다.

- **이슈:**
  - UI-05를 새로 기록했습니다.
  - 이 환경에서 `npx tsc --noEmit`는 프로젝트에 설치된 TypeScript를 찾지 못하고, npm에서 관련 없는 `tsc@2.0.4` 패키지를 받아 안내문만 출력했습니다. 프로젝트 파일은 바뀌지 않았고, 타입 검사는 `node_modules/.bin/tsc`로 대신 돌려 통과했습니다.
  - 세션 임시 폴더를 다른 작업과 같이 쓰고 있어서 첫 빌드 결과물이 덮어써졌습니다. 고유한 이름의 폴더로 다시 빌드해 확인했습니다.
- **해결:** 코드 쪽 불일치(선언값)는 정리했고 검사 스크립트로 확인했습니다. 화면에서 고르게 보이는지는 확인하지 않아 해결로 보지 않습니다.
- **남은 문제:**
  - 실제 화면 간격 측정(1440×900, 390×844), E2E 테스트, 12크기×6상태 넘침 검사를 하지 못했습니다. 이전 화면 검증 결과는 바뀐 CSS 기준으로는 더 이상 유효하지 않습니다.
  - 코드로 계산하면 버튼 칸이 데스크톱 7px, 휴대폰 6px 커집니다. 390×844 추천 상태에서 말풍선 칸이 약 274px에서 268px로 줄어 내용이 접히는 기준(260px)에 가까워지므로 꼭 확인해야 합니다.
  - 카드 안 글줄 사이 간격(라벨 → 큰 좌표 → 제목 → 설명)은 이번 규칙에 넣지 않았습니다.
