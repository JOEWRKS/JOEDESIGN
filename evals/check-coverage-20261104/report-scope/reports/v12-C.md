메인 화면 간격 규칙을 정해 DESIGN.md에 적고 `src/style.css`를 맞췄으며, 검사 스크립트 `work/design/spacing-check.mjs`를 추가했습니다. 코드로 계산한 검사는 3281/3281 통과했습니다. 다만 브라우저를 못 써서 실제 화면에서 잰 간격은 아직 하나도 없습니다.

- **작업**
  - 말씀하신 문제는 코드로도 확인됩니다. 원인은 카드·버튼 아래에 붙은 입체 그림자(3~10px)를 간격 계산에서 빼지 않은 것입니다. 변경 전 1440×900 대국 화면에서 그림자 끝부터 다음 테두리까지 간격은 이랬습니다.
    - 카드끼리 4~9px
    - 큰 버튼과 그 아래 되돌리기 안내 사이 1px
    - 금수 안내와 버튼 사이 16px (margin과 gap이 겹침)
    - 버튼 묶음 안 가로 간격 8·10·12px이 섞여 있음
    - 390×844에서도 카드끼리 3~7px, 버튼과 안내 사이 2px
  - 규칙(제안 값):
    - **칸 사이**: 12px, 휴대폰이나 키 작은 화면은 8px. 그림자 깊이만큼 아래 자리를 미리 비워서, 정해 둔 간격이 그대로 눈에 보이게 했습니다.
    - **버튼 사이**: 8px
    - **카드 안 줄 사이**: 묶음 사이 8px(휴대폰 4px), 짝 줄 사이 4px
    - **안쪽 여백**: 큰 말풍선 16/20px, 보조 카드 12/16px, 안내 상자 4/12px
    - 시작 화면의 제목과 첫 카드 사이만 24px로 예외입니다.
  - 색·모양·배치·판 크기 공식은 바꾸지 않았습니다. 시작 화면과 대국 화면 둘 다 적용했습니다.

- **업데이트 파일**
  - `src/style.css`

  - `work/design/spacing-check.mjs` (새 파일)

  - `TASK.md` (2026-11-05 항목)

  - 커밋은 하지 않았습니다.

- **이슈**: 휴대폰에서 큰 버튼의 비활성·초록 상태 그림자가 7px에서 6px로 바뀌었습니다. 다른 큰 버튼과 맞추려고 그렇게 했습니다.

- **해결**: 코드 기준으로만 확인했습니다.
  - `npm run check:spacing` 3281/3281: 12개 화면 크기 × (시작 화면 + 대국 화면에서 말풍선 칸 높이를 4가지로 가정), 밝은 화면, 스타일 코드로 계산한 값입니다(실제 화면 측정 아님).
  - 같은 스크립트를 변경 전 코드에 돌리면 칸 사이 규칙이 38/1012만 통과합니다. 어긋나면 잡아낸다는 것을 확인했습니다.
  - `npx tsc --noEmit` 통과. `npx vitest run`은 87개 통과, 1개 건너뜀입니다. 건너뛴 것은 엔진 파일이 없어 원래 건너뛰는 시험이고 이번 변경과 무관합니다.
  - 빌드도 통과했습니다. 결과물은 임시 폴더에 만들었습니다.

- **남은 문제**
  - 실제 화면 대조가 없습니다. 손으로 계산한 값과 한 곳을 맞춰 봤을 뿐, 화면에서 잰 것은 아닙니다.
  - 12크기 화면 넘침 검사와 E2E를 다시 돌리지 못했습니다. 높이 합이 몇 px 바뀌었습니다. 코드로 계산하면 버튼 영역이 데스크톱에서 약 11px 커지고, 대신 말풍선 칸에 남는 높이는 휴대폰에서 약 13px 늘어납니다.
  - 검사 범위 밖: 숨김 요소 조합, 라벨 줄과 버튼 사이, 상단 칩·버튼 안쪽 여백, 도움말 창.
  - 간격 값을 사용자가 아직 확인하지 않았습니다. 그래서 "확인 대기"로 기록했습니다.
