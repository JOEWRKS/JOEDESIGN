간격 규칙을 정해 DESIGN.md에 적고, `src/style.css`를 그 규칙에 맞췄고, 검사 스크립트도 추가했습니다. 다만 이 세션은 브라우저가 없어 실제 화면에서 간격을 재 보지는 못했습니다. 간격 검사 결과는 위반 0건인데, 이는 `src/style.css`의 규칙 414개 전체(모든 상태·미디어·컨테이너 조건 포함)를 코드로 읽은 결과입니다. 7개 크기(1440×900~360×640)의 토큰 값도 미디어 조건으로만 계산한 것이고, 렌더 측정은 아닙니다.

- **작업:**
  - 원인을 코드에서 찾았습니다. 블록 사이 간격 값은 숫자로 맞춰져 있었지만, 블록마다 아래 그림자 깊이(3~10px)가 달라 그 간격을 서로 다르게 잡아먹었습니다. 금수·엔진 안내 줄에는 margin 8px가 따로 붙어 있었습니다. 그래서 보이는 간격이 데스크톱 1~16px, 휴대폰 2~16px로 흩어져 있었습니다.
  - 규칙은 '보이는 간격'(위 요소 그림자 끝 → 다음 요소 테두리) 기준, 4px 단위입니다.

    | 간격 | 값 |
    | --- | --- |
    | 카드·버튼 줄·안내 줄 사이 | 12px (폭이나 높이가 700 이하면 8px) |
    | 작은 버튼 사이 | 8px |
    | 큰 버튼(두기·취소·되돌리기) 사이 | 12px |
    | 시작 화면 구역 사이 | 16px (높이 720 이하면 8px) |
    | 공간이 모자라 접힌 상태 | 4px |

  - 그림자가 있는 블록과 버튼은 그림자 깊이만큼 아래 여백을 따로 잡아, 정한 간격이 그대로 보이게 했습니다.
  - 검사 스크립트는 여섯 가지를 봅니다: 토큰 값, 간격에 숫자를 직접 쓰지 않았는지, 그림자 깊이, 그림자만큼의 여백, 블록에 따로 붙인 숫자 margin, 검사 대상 클래스가 화면 코드에 실제로 있는지. `--self-test`로 일부러 어긋나게 만든 CSS 6가지를 넣어 보니 모두 위반으로 잡았습니다. 수정 전 CSS에 돌려도 위반을 여러 건 잡습니다.

  - 눈에 보이는 변화가 따라옵니다:

- **남은 문제:**
  - SPACING-01은 열려 있습니다. 실제 화면에서 간격을 재 검사 결과와 대조하는 것, 넘침과 E2E 확인이 남았습니다. DESIGN.md의 검사 범위 표 모든 행에 "실제 화면 대조 안 함"이라고 적어 두었습니다.
