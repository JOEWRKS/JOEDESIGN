간격 규칙을 정해 DESIGN.md에 적고, `src/style.css`를 그 규칙에 맞췄고, 검사 스크립트 `work/design/spacing-check.mjs`를 추가했습니다. 코드 검사는 6/6 통과했지만, 브라우저를 못 써서 실제 화면에서 간격이 고르게 보이는지와 잘리는 곳이 없는지는 확인하지 못했습니다.

**원인:** 카드와 버튼 아래의 입체 그림자(3~10px)가 간격 안에 그려져서, 같은 간격 값이어도 눈에 보이는 간격이 블록마다 달랐습니다. 1440×900 기준으로 카드 사이가 4·5·7·9px, 착수 버튼에서 아래 안내 줄까지 1px, 금수 안내 아래는 16px였습니다. 간격 값 자체도 6/8/10/12/14/18px로 흩어져 있었습니다.

**정한 규칙** (지금은 제안 단계이고 아직 승인 전입니다):
- 그림자가 있는 블록은 그림자 깊이만큼 아래 자리를 스스로 잡습니다. 그래서 간격 값이 그대로 눈에 보이는 간격이 됩니다.
- 간격은 4px 단위 값과 아래 네 가지 역할 값만 씁니다.

| 간격 | 1440×900 | 390×844 |
|---|---|---|
| 판 · 말풍선 영역 · 버튼 영역 사이 | 16px | 12px |
| 카드 · 안내 줄 사이 | 12px | 8px |
| 큰 버튼 사이 | 12px | 8px |
| 작은 버튼 · 칩 사이 | 8px | 8px |

- 같은 줄의 버튼은 그림자 깊이를 맞춥니다. 그래서 취소 버튼 그림자가 5px에서 7px(휴대폰 6px)로 깊어졌습니다.

**보고 형식 6항목**
- **작업:** 위 규칙을 DESIGN.md에 적고 `src/style.css`의 바깥 간격을 맞췄습니다. 카드 안쪽 여백, 도움말 창, 새 게임 확인 창은 이번에 손대지 않았습니다. 검사 스크립트를 추가했고 TASK와 ROADMAP을 갱신했습니다. 커밋은 하지 않았습니다.
- **업데이트 파일:** `src/style.css`, `work/design/spacing-check.mjs`(새 파일), `DESIGN.md`, `TASK.md`, `ROADMAP.md`
- **이슈:** `npx tsc`는 이 폴더에서 프로젝트의 TypeScript를 찾지 못했습니다. 대신 이름만 같은 무관한 패키지 `tsc@2.0.4`를 프로젝트 `.cache/npm`에 받아 안내 메시지만 내고 실패했고, 다른 코드는 실행되지 않았습니다. `npx vitest run`은 3분 넘게 끝나지 않아 멈추고, 두 검사 모두 프로젝트 안의 실행 파일로 다시 돌렸습니다.
- **해결:**
  - 간격 검사 `node work/design/spacing-check.mjs`는 6/6 통과입니다.
  - 고치기 전 CSS로 돌리면 1/6만 통과해서, 검사가 실제로 어긋남을 잡는다는 것도 확인했습니다. 일부러 넣은 위반 3건도 각각 잡혔습니다.
  - `node node_modules/typescript/bin/tsc --noEmit` 통과.
  - `node node_modules/vitest/vitest.mjs run`은 87개 통과, 1개 건너뜀입니다. 기존 기록은 88/88이었는데, 건너뛴 이유는 확인하지 않았습니다.
- **남은 문제:**
  - 실제 화면에서의 간격, 넘침, 스크롤 없음은 측정하지 않았습니다. E2E 테스트도 돌리지 않았습니다.
  - 휴대폰에서는 말풍선 영역 내용이 약 7px 늘어날 수 있다고 계산했습니다(화면 측정은 안 함). 그래서 키가 작은 화면에서는 마지막 줄이 잘릴 위험이 있습니다.
  - 사용자 시각 확인은 아직 없습니다.
- **다음 작업:** 브라우저를 쓸 수 있는 세션에서 `work/design/capture-matrix.mjs`(12개 크기 × 6개 상태)와 E2E를 다시 돌리고, 카드 사이 실제 간격을 재야 합니다. 그 뒤 사용자가 화면을 보고 확인하면 됩니다.

**질문:** "메인 화면"을 대국 화면으로 보고 작업했습니다. 시작 화면은 세 영역 사이 간격만 맞췄고, 그 안의 돌 색·강도 버튼 줄은 그대로 두었습니다. 시작 화면 안쪽도 같은 규칙으로 맞출지 알려 주세요.
