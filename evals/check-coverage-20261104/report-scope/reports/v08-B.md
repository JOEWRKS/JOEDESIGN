간격 규칙을 정해 DESIGN.md에 적었고, src/style.css를 그 규칙에 맞췄고, 검사 스크립트 `work/design/spacing-check.mjs`를 추가했습니다. 코드 검사는 위반 0건으로 통과했습니다. 다만 이 세션에서는 브라우저를 쓸 수 없어서 실제 화면에서 간격과 넘침은 재지 못했습니다. 그래서 디자인 규칙은 제안(DRAFT) 상태이고, 이 항목도 확인 대기로 남겨 두었습니다.

- **작업**:
  - 간격이 제각각으로 보인 원인을 코드에서 찾았습니다. 카드와 버튼마다 아래로 떨어지는 입체 그림자 깊이가 3~8px로 다른데, 간격은 그림자를 빼지 않고 줬습니다. 그래서 그림자 끝에서 다음 카드까지 실제로 보이는 간격이 1440×900에서 4/7/5/9/8/1px, 390×844에서 4/6/5/3/7/8/1px로 섞여 있었습니다. 큰 버튼과 아래 줄 사이는 1~2px뿐이었습니다.
  - 규칙은 이렇게 정했습니다.
    - 간격 값은 2·4·8·12·16·20·24px 척도만 씁니다.
    - 카드·안내 줄·버튼 줄 사이의 보이는 간격은 데스크톱·태블릿 12px, 휴대폰 8px 하나로 맞춥니다. 각 덩어리가 자기 그림자 깊이(`--drop`)만큼 아래 여백을 더하는 방식입니다.
    - 카드 안 줄 간격은 블록 사이 8/4px, 짝이 되는 줄(제목과 설명 등) 사이 4/2px입니다.
    - 버튼끼리는 8px, 큰 행동 버튼 줄은 덩어리 간격과 같습니다.
    - 카드 안쪽 여백은 주 말풍선, 보조 카드, 안내 줄의 세 단계로 나눴습니다.
    - 큰 버튼 그림자 깊이는 모든 상태에서 하나(`--btn-drop`)로 씁니다. 휴대폰에서 비활성·두기 상태만 7px로 섞이던 문제도 함께 고쳤습니다.
  - 배치·색·글자·그림자 모양은 바꾸지 않았습니다(승인된 v0.3 방향 안의 국소 수정).
  - 검사 스크립트는 브라우저 없이 CSS를 읽고, 프로젝트가 쓰던 12개 화면 크기마다 미디어 조건을 계산해 S0~S8 규칙을 확인합니다. 위반이 있으면 종료 코드 1을 냅니다. 실행은 `node work/design/spacing-check.mjs`입니다.

  - `TASK.md` (#spacing)

- **이슈**: SPACE-01(메인 화면 간격 불일치)을 열었습니다. 코드는 고쳤고 실제 화면 확인을 기다립니다.
- **해결** (코드 검사 기준):
  - 바뀐 CSS로 돌린 `spacing-check`는 위반 0입니다. 12개 크기 모두 보이는 간격이 12px(데스크톱·태블릿) 또는 8px(휴대폰)로 나옵니다.
  - 같은 검사에 변경 전 CSS를 넣으면 위반 575건이 나옵니다. 일부러 어긋나게 바꾼 사본 2개도 각각 실패로 잡혔습니다.
  - `npx tsc --noEmit`는 통과했습니다.
  - `npx vitest run`은 87개 통과, 1개 건너뜀입니다. 건너뛴 1개는 엔진 파일이 이 작업 폴더에 없어서 생긴 것이고 CSS와는 관계없습니다.
- **남은 문제**:
  - 실제 렌더 측정, 12크기×6상태 넘침 확인, E2E는 이번 세션에서 실행하지 못했습니다.
  - 태블릿 세로 화면(768×1024, 820×1180)은 판 크기 계산에 실제 간격을 넣으면서 판이 약 22px 작아집니다. 휴대폰 크기는 그대로이거나 1px 차이입니다. 둘 다 계산값이고 화면에서 보지 않았습니다.
  - 상단 대결줄, 판 위 표식, 도움말·새 게임 확인 창, 버튼 안쪽 여백, 화면 가장자리 여백은 이번 규칙 범위 밖입니다.
  - 확인이 필요한 질문:
    1. "메인 화면"이 게임 화면인가요, 시작 화면인가요? 두 화면이 같은 부품을 써서 둘 다 맞췄습니다.
    2. 휴대폰 간격 8px, 카드 안 4px(기존 6px)이 답답하지 않은가요?
    3. 그림자 보정 대신 그림자 깊이 자체를 하나로 통일하길 원하나요? 시각 위계가 바뀌는 일이라 이번에는 하지 않았습니다.
- **다음 작업**: 브라우저를 쓸 수 있는 세션에서 바뀐 빌드를 12크기×6상태로 캡처해, 보이는 간격과 넘침 0을 실제 화면에서 재고 E2E를 다시 돌립니다. 그다음 새 간격 값을 확인받으면 SPACE-01과 CO3를 닫을 수 있습니다.

명시적으로 하라고 한 JOEDESIGN 단계 중 몇 가지는 하지 못했습니다. 독립 검토(R/C1)에 쓸 전문 스킬(Impeccable, UI UX Pro Max, web-design-guidelines)이 이 작업 폴더에 없었고, 화면 캡처 실행 권한도 없었습니다. 그래서 별도 검토를 거치지 않은 담당자 판단 기준의 결과이며, 실제 화면에서의 시각 판단은 확인되지 않았습니다.
