## 바뀐 것 (`skills/joedesign/scripts/report-check.mjs`)

R7은 1.3.3과 같이 "주입을 말하는 보고에서 넷째 칸이 `rendered`뿐인 줄"을 줄마다 지적하고, `rendered (own css)` 줄은 그대로 통과한다. 바뀐 것은 목록 밖 문장으로 넘기는 허용 경로다.

| 18부가 찾은 원인 | 1.3.3 | 1.3.4 후보 |
| --- | --- | --- |
| 1. 허용 문장이 검사 이름 첫 낱말(`C1`)을 들어야 함. 사람은 페이지 이름("요청 화면")을 듦 | 검사 이름만 | 검사 이름 **또는 그 줄의 페이지 이름**(검사 칸의 괄호 속, 쉼표 뒤, 없으면 첫 낱말 뒤 나머지). 반대로 다른 줄의 페이지만 들고 이 줄의 페이지는 들지 않은 절은 이 줄을 넘기지 못함(r02의 확인 화면 문장) |
| 2. 부정어 부분 일치: `마지막`의 `막`, 템플릿 어휘 `not spot-checked`의 `not` | `막`, `못`, `\bnot\b` 등 글자 단위 | 낱말 형태로: `못`은 못해·못했·못함·못한·못할·못하 또는 뒤에 공백, `막`은 막아·막혀·막힌·막음·막았·막는·막고·막다·막은·막을·막기, `not`은 `not spot-checked`·`not checked`·`not measured`를 제외. 읽지·않·차단·n't·failed·=false·blocked·without는 그대로 |

페이지 이름 집합은 결과 목록의 모든 줄(주입 표시 줄 포함)에서 모은다. 처음에는 `rendered`뿐인 줄에서만 모아 `(injected css)` 줄의 페이지("확인 화면")를 몰랐고, 새 테스트가 이를 잡아 고쳤다.

지적 문구 끝만 바뀜: "say so outside the list naming this check or its page". `--verify` 종료 코드 의미, 도장 형식은 같다. `references/conformance.md` R7 설명과 `templates/DESIGN.md` 측정 모드 문단에 한 절씩("검사 이름 또는 페이지").

## 확인되지 않은 것

- 행동 효과(유료 실행 0회). 18부에서 에이전트는 4/4 `rendered (own css)`를 썼으므로, 이 보정이 실제 보고에서 쓰일 빈도는 모른다. 보정의 목적은 괄호 없이 쓴 올바른 보고를 떨어뜨리지 않는 것이다.
- 페이지 이름 추출은 검사 칸 형식에 기댄다. 괄호도 쉼표도 없는 긴 검사 이름(`C1 상자 간격 오른콽 끝 요청 화면`)은 첫 낱말 뒤 전체가 페이지 이름이 되어 본문과 맞지 않을 수 있다. 그때는 검사 이름(`C1`) 경로나 `rendered (own css)`로 넘긴다.
- 부정 낱말 목록은 18부 실물에서 나온 형태 기준이다. `막다`·`못하다`의 다른 활용(막았으나, 못 읽음 등)은 뒤 글자 목록에 있는 것만 잡는다.
- 빗금(`/`)을 절 경계로 쓰므로 `check 4 / observed 9` 같은 수치 표기도 나뉘지만, 허용 판정에는 영향이 없었다(수치 절에는 자기 CSS 낱말이 없음).
- 개인 설치본·태그·Release 없음. 게시는 사용자 결정.
